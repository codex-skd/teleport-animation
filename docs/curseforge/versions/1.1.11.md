<h2>v1.1.11 - Fix falling through the floor on waystone arrival</h2>

<h3>Fix</h3>
<ul>
<li><strong>Player fell through the floor and landed one level below on arrival</strong>: the transition animation's planned arrival position used the waystone's base block Y instead of its standing surface (Y+1), so the arrival camera/preview descended a full block through the floor before snapping to the real player position. The arrival target now correctly targets the waystone's standing surface, both for regular Waystones and Warp Plates.</li>
<li><strong>Silent teleport failures</strong>: if all reflection-based calls into Waystones' teleport manager failed, the player was silently left un-teleported while the transition animation still played as if it had succeeded. This is now logged as an error so a real API mismatch is no longer invisible.</li>
</ul>

<h3>Technical Changes</h3>
<ul>
<li><code>WaystonesTeleportHandler.readWaystoneFeet()</code>, <code>WaystonesWarpPlateHandler</code> and <code>TeleportClient</code> now compute the planned arrival feet as <code>(pos.getX()+0.5, pos.getY()+1.0, pos.getZ()+0.5)</code> instead of using the raw block Y.</li>
<li><code>WaystonesTeleportHandler.runWaystonesTeleport()</code> refactored into a shared <code>invokeWaystonesTeleport()</code> helper; if all four Waystones API signatures (<code>tryTeleport</code>, <code>teleport</code>, <code>tryTeleportAsync</code>, <code>forceTeleportAsync</code>) fail, the failures are now logged via <code>LOGGER.error</code> instead of being silently discarded.</li>
<li>Confirmed via bytecode inspection of the Waystones 26.2.0.5 jar that the mod's own <code>WaystoneTeleportManager.resolveDefaultDestination()</code> already places the entity at the block's center (<code>+0.5</code> on every axis); the real server-side teleport was never affected by this bug — only this mod's own arrival animation preview.</li>
</ul>
