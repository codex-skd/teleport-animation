<h2>v1.1.14 - Fix landing underground on long-distance waystone trips</h2>

<h3>Fix</h3>
<ul>
<li><strong>Player lands underground on arrival, especially on long trips</strong>: Waystones' synchronous <code>tryTeleport()</code>/<code>teleport()</code> entry points do not force the destination chunk to fully load before resolving the arrival spot, unlike the async variants (<code>tryTeleportAsync</code>/<code>forceTeleportAsync</code>). This mod's reflection bridge always tried <code>tryTeleport</code> first and treated "no exception thrown" as success, so it almost never reached the chunk-loading async variants. If the destination chunk wasn't already loaded (common on long trips to distant waystones), Minecraft returned default empty-air block data for those positions, causing Waystones' own free-space check next to the waystone to wrongly pick an offset tile that was actually a staircase shaft or basement opening in the (unloaded) real structure below — the player then fell into the waystone build's underground section on arrival.</li>
</ul>

<h3>Technical</h3>
<ul>
<li><code>WaystonesTeleportHandler.runWaystonesTeleport()</code> now force-loads the destination waystone's chunk and its 4 cardinal neighbors (matching Waystones' own chunk preload set) before attempting any of the 4 reflection-based teleport calls, so all of them read real block data instead of defaulted empty air.</li>
<li>New <code>readWaystonePos()</code> / <code>forceLoadDestinationChunks()</code> helpers in <code>WaystonesTeleportHandler</code>.</li>
<li>Unrelated to the 1.1.11/1.1.12 Y-offset fixes (those corrected the camera preview position calculation; this fixes the actual arrival position computed by Waystones when the destination chunk wasn't loaded).</li>
</ul>
